# conohavps_instance_autobackup (Resource)

Enables auto-backup of the volumes attached to a server. The boot storage volume and, when attached, the additional storage volume are backed up. Destroying this resource disables auto-backup of the server.

The API cannot read back whether auto-backup is enabled or its retention, so this resource keeps the values it applied and only detects that the server itself was deleted. Changes made outside Terraform are not detected. The API has no update operation, so changing `schedule` or `retention` disables auto-backup and enables it again.

## Example Usage

```terraform
# Back up the volumes attached to the server every day and keep backups for 30 days
resource "conohavps_instance_autobackup" "example" {
  instance_id = "11111111-1111-1111-1111-111111111111" # Replace with your server ID
  retention   = 30
}
```

## Schema

### Required

- `instance_id` (String) The ID of the server to enable auto-backup for. Changing this value will force the resource to be recreated.

### Optional

- `retention` (Number) The retention period of backups in days, from 14 to 30. Defaults to 14. Changing this value will force the resource to be recreated.
- `schedule` (String) The backup schedule. Allowed value: `daily`. Defaults to `daily`. Changing this value will force the resource to be recreated.

### Read-Only

- `id` (String) The ID of the server (same as `instance_id`).

## Import

Auto-backup can be imported using the server ID. The API cannot read back the retention, so it is taken as 14 days unless given as `<instance_id>/<retention>` .

```shell
$ terraform import conohavps_instance_autobackup.example {{server_uuid}}/30
```
